# 附录 E 本文没有展开的内容

本文只讲一件事：软件需求如何由名变实。写作过程中还涉及下面这些话题，它们都有价值，但会稀释主线，所以只在这里列出。工具类信息变化很快，这里提到的都是 2026 年 9 月前后的状态，使用前请重新确认。

| 话题 | 为什么没展开 | 想深入可以看什么 |
|---|---|---|
| AI 原生 SaaS 与项目管理工具（禅道、ONES 等） | 属于工具选型，与“需求由名变实”无直接关系 | 判断标准：拿掉 AI 产品还能不能用；能否一句话完成跨对象操作；AI 操作是否有权限边界与审计；能否被外部 Agent 调用 |
| 阿里体系中的对应产品 | 同上 | 云效（DevOps 与项目协作）、钉钉项目（Teambition） |
| 测试管理工具 | 同上 | TestRail、Qase、Xray、Zephyr、TAPD 等；关注自动化结果如何回传 |
| Jira 与 Atlassian 产品线 | 同上 | 注意 Data Center 已停止对新客户销售，2029 年到期 |
| ASPICE 专用平台 | 本文把 ASPICE 定位为诊断器，不做工具推荐 | Polarion、codebeamer、Jama、DOORS 等；先用小范围 PoC 验证 |
| 需求在不同工具里的写法 | 读者不一定用这些工具 | 同一条需求在 DOORS、Jira、ReqIF、Sphinx-Needs、StrictDoc 中的对照 |
| 追溯层架构与文档即代码 | 属于实现细节，适合独立成册 | 各环节用最合适的工具加追溯层；每晚跑缺口检查；用快照弥补基线 |
| 组织心理学概念 | 正文只保留最必要的一小段 | 角色模糊与角色冲突、责任分散、社会惰化、多数无知、心理安全 |
| 丰田的其余体系 | 正文只取三个想法 | TPS 全景、TQC、方针管理、TBP、A3 |
